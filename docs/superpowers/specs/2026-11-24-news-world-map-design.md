# 新闻世界地图 — 设计文档

日期：2026-11-24
状态：已确认（关键决策见文末「用户决策」）

## 1. 目标

做一个**新闻世界地图**：把国际新闻定位到世界地图上，每天累加更新；用户可以在地图上定位/点击新闻点，并按日期筛选新闻（默认最近 7 天）。

交付形态：**本地文件**（源码 + 数据 + 一键脚本），用户自行运行。每日更新通过定时任务在本地工作区跑采集器实现。

## 2. 关键约束（实测结论）

沙箱/运行环境探测结果，直接决定了技术选型：

| 探测项 | 结果 | 影响 |
|---|---|---|
| GDELT DOC/GEO API | 本机 IP 被限流封禁（429 / 404） | 不依赖 GDELT |
| OSM 瓦片 `tile.openstreetmap.org` | 不可达 | **不���瓦片地图**，改用纯矢量国界 |
| Guardian / 路透 / 半岛 / ABC 中文 等源 | 不可达 | 只用实测可达的源 |
| jsDelivr / unpkg CDN | 可达 | Leaflet 等依赖本地内置，运行时零外链 |
| Open-Meteo 地理编码 API | 可达 | 用于构建地名库 + 运行时未知地名解析 |
| feeds.npr.org / CBS / France24 / Sky / UN News / ABC | 可达且新鲜 | 主数据源 |

结论：**整个站点离线可渲染**（矢量地图 + 内置 JS + 本地 JSON 数据），不依赖任何瓦片服务或运行时 CDN。

## 3. 架构

```
采集侧（Python，仅标准库）          展示侧（静态站点）

```

### 3.2 地理定位（核心）

RSS **不含任何地理字段**（已逐源检查：无 `geo:lat`/`georss:point`/GeoJSON），因此定位完全靠文本分析：

1. **地名库 gazetteer.json**
   - 250 个国家：`world-countries` 数据集 → 英文名/官方名/中文名(zho)/异体拼写/属格形式/经纬度/首都
   - 250 座首都：Open-Meteo 地理编码取经纬度
   - ~380 座主要城市 + 热点地区：人工策展清单（中文名 + 英文名 + 别名），Open-Meteo 地理编码
   - 区域质心：按国家集合聚合，用于「区域源」兜底
2. **匹配打分**（标题权重 > 摘要权重；具体地点 > 国家）
   - 城市出现在标题 → 1.0
   - 城市出现在摘要 → 0.8
   - 国家出现在标题 → 0.7
   - 国家出现在摘要 → 0.5
   - 仅命中源所属国家 → 0.25（最低兜底）
3. **未知地名自扩展**：标题中未收录的大写专名，若能解析到人口 ≥ 10 万的 PCLI/PPLA/PPLC 地点，则采纳并写入地名库缓存——地名库随采集自动生长。
4. 每条新闻标注 `confidence` 与 `match_kind`，前端用不同颜色/大小区分，绝不把推断伪装成精确坐标。

### 3.3 累加与去重

- 唯一键 = 标题规范化后的 SHA1 前 12 位（去标点、大小写折叠、压缩空白）；同时用去查询参数的 URL 做二次键
- `data/news.json` 保存全量历史，默认保留 90 天（可配），按发布时间倒序
- 每次采集 = 旧数据 + 新抓取项，按唯一键合并 → 写回，天然「每天累加」

### 3.4 前端

- **地图**：Leaflet 1.9.4（本地内置）+ `world-atlas` TopoJSON（110m 国界，本地内置）→ `topojson-client` 转 GeoJSON → `L.geoJSON` 绘制。无瓦片、无外链、无限流。
- **新闻点**：自研网格聚合（按屏幕像素分桶，桶宽 70px）。单条 → 圆形标记；多条 → 半径随数量变化的聚合圆 + 数字标签，点击缩放直至拆分。
- **交互**：
  - 点击新闻点 → 详情卡片（图片、标题、来源、时间、地点中英名、置信度徽章、原文链接）
  - 「＋ 添加新闻点」模式 → 点击地图任意位置添加自定义条目（标题/备注/链接），存 localStorage，以独立颜色渲染
  - 侧栏列表 ↔ 地图双向联动（点列表 → 飞行定位；点地图 → 高亮列表项）
- **日期筛选**：起止日期输入 + 快捷区间（24 小时 / 7 天 / 30 天 / 全部）；**默认最近 7 天**；变化即时生效并更新计数
- **搜索**：标题/摘要关键词
- **统计条**：区间内条数、覆盖国家数、Top 来源
- **每日柱状图**：按天统计条数，点击柱子跳到那一天

### 3.5 每日更新

`cron_create` 每天 07:00（Asia/Shanghai）触发，任务在固定会话中运行：
执行 `python3 -m collector.collect` → 合并进 `data/news.json` + 重新生成 `data/news-data.js` → 校验条数与时间范围 → 汇报。

浏览器侧另有一层：加载时把服务端数据与 localStorage 中更新的条目合并，保证「打开即最新」。

## 4. 错误处理

- 单个源失败（超时/非 200/解析异常）→ 记 warning，继续其他源，不中断整轮
- 429 → 该源本轮跳过，退避后重试一次
- Open-Meteo 解析失败 → 退回已知地名库匹配；不缓存失败结果
- 地名库缺失 → 该条新闻标记为未定位（前端不画点，但在侧栏「未定位」分组可见）
- 采集结果为 0 条 → 不覆盖已有数据（保护历史），报警

## 5. 验收标准

1. `run.sh` 一条命令：采集 → 起本地服务 → 浏览器可打开
2. 地图渲染出世界国界 + 新闻点，无需外网瓦片
3. 默认展示最近 7 天；日期筛选可用；条数统计随筛选变化
4. 点击新闻点弹出详情；聚合点可展开
5. 第二次采集后条数单调递增（累加生效），且不产生重复
6. 定时任务能正常跑完并更新数据

## 6. 用户决策（2026-11-24 确认）

- 数据源：**只用 RSS 聚合，免费免 key**（不接 NewsAPI/GNews）
- 交付：**只要本地文件，用户自己跑**（不发布公开网址）
- 每日累加：**定时任务每天跑采集**（更新本地数据集，不涉及重新部署）
